### Part B — Objectives

- compare full-copy snapshots with change logs.

### Part C — Core content
- A successful union changes only a constant number of fields if path compression is disabled.
- Store the child root, parent root, and parent root's previous size in history.
- Use union by size to keep tree height O(log N).
- `snapshot()` returns the current history size.
- `rollback(token)` undoes history entries in LIFO order until the stored size is restored.
- Complexity: find O(log N), unite O(log N), snapshot O(1), one successful-union undo O(1), rollback O(K) for K undone unions, storage O(N+U).

### Part D — Worked Example
Problem: temporary network links with LINK / SAVE / RESTORE / SAME operations.
The worked example demonstrates saving a history-size token, adding temporary connectivity, checking it, rolling back, and verifying that connectivity returns exactly to the saved state.

## Response 2 — Q&A

### Q1. 실제 코딩 테스트에서도 직접 구현해야 하는가?
대체로 그렇다. C++ 표준 라이브러리에는 ordinary DSU나 Rollback DSU가 표준 컨테이너/알고리즘으로 제공되지 않는다. 따라서 표준 C++ 환경을 기준으로 하면 직접 구현할 준비를 하는 것이 안전하다.

- ordinary DSU는 `parent`, `size/rank`, `find`, `unite` 정도의 짧은 구현을 직접 작성하는 경우가 흔하다.
- Rollback DSU는 ordinary DSU에 non-compressing `find`, change history, snapshot token, rollback을 추가해야 하므로 더 직접적인 구현 능력이 필요하다.
- 플랫폼/회사 규칙에 따라 개인 템플릿이나 제공 라이브러리를 사용할 수 있지만 이는 시험마다 다르다.
- ordinary DSU 라이브러리가 제공되더라도 rollback 지원 여부는 별도로 확인해야 한다.

Practical target: 코드 전체를 문자 단위로 암기하기보다 `root search -> union by size -> log old state -> snapshot -> LIFO rollback` 구조를 독립적으로 재구성할 수 있어야 한다.
