\chapter{S1-B --- Sorting \& Bounds}

\section{Part A --- 위치와 선수지식}

\subsection{현재 위치}
S1-B는 Stage 1의 두 번째 Learning Unit이다. S0-B에서 \code{sort}와 custom comparator의 기본 문법을 접했고, S1-A에서는 \code{set}/\code{multiset}과 ordered bound query를 사용했다. 이번 Unit에서는 이 두 흐름을 연결하여 \textbf{정적 또는 거의 정적인 sequence를 한 번 정렬한 뒤 그 순서를 반복 query에 재사용하는 방법}을 다룬다.

핵심 범위는 다음과 같다.
\begin{itemize}
\item \code{std::sort}와 정렬 기준
\item custom comparator와 tie-breaking
\item 정렬된 \code{vector}의 \code{lower\_bound}, \code{upper\_bound}
\item 중복 원소와 반열린 경계
\item 같은 값과 값 구간의 원소 개수 계산
\item sorted \code{vector}와 \code{set}/\code{multiset}의 선택
\end{itemize}

이번 Unit은 STL bounds를 사용하는 단계다. Binary Search를 직접 구현하고 loop invariant를 설계하거나 answer space에 Binary Search를 적용하는 기법은 Stage 3의 Binary Search Family에서 다룬다.

\subsection{왜 지금 배우는가}
정렬되지 않은 배열에서 “$x$ 이상인 첫 값”, “$[L,R]$ 안의 값 개수” 같은 query를 반복하면 query마다 $O(N)$ scan이 필요할 수 있다. 데이터가 변하지 않는다면 한 번 정렬해 순서를 만든 뒤 각 경계를 $O(\log N)$에 찾을 수 있다.

따라서 반복 scan의
\[
O(NQ)
\]
를
\[
O(N\log N+Q\log N)
\]
으로 바꿀 수 있는 경우가 많다.

\subsection{선수지식}
\begin{itemize}
\item \code{vector}, iterator
\item \code{sort(first,last)}
\item 함수 또는 lambda comparator
\item $O(N)$, $O(\log N)$, $O(N\log N)$
\item S1-A의 ordered container와 bound query
\end{itemize}

\subsection{Core Decision Boundary}
\begin{center}
\begin{tabularx}{\textwidth}{p{4.6cm}X}
\toprule
선택 상황 & 판단 기준 \\
\midrule
선형 탐색 vs sort + bounds & 같은 static 데이터에 query가 반복되는가? \\
sorted \code{vector} vs ordered container & 중간 insert/erase가 계속되면 set/multiset, batch/static이면 sorted vector를 우선 검토한다. \\
\code{lower\_bound} vs \code{upper\_bound} & 이상 경계인지 초과 경계인지 구분한다. \\
default vs custom comparator & 기본 오름차순으로 충분한지, 여러 field와 tie-break가 필요한지 본다. \\
정렬 기준 vs 검색 기준 & bounds가 전제하는 ordering과 실제 정렬 기준이 호환되어야 한다. \\
\bottomrule
\end{tabularx}
\end{center}

\subsection{Immediate Coverage Floor}
\begin{itemize}
\item sorted vector에서 lower/upper bound를 사용한 boundary query
\item duplicates가 있을 때 두 bound의 차이 설명
\item custom comparator로 복합 정렬 기준 구현
\item update 패턴에 따라 sorted vector와 ordered associative container를 선택
\end{itemize}

\section{Part B --- 학습 목표}
이 Unit을 마치면 다음을 독립적으로 수행할 수 있어야 한다.
\begin{enumerate}
\item \code{std::sort}로 ascending/descending 정렬을 구현한다.
\item 복합 기준 custom comparator와 tie-break를 정확히 구현한다.
\item comparator를 strict ordering으로 작성하고 \code{<=}, \code{>=} 같은 비엄격 비교를 피한다.
\item \code{lower\_bound(x)}를 첫 $\ge x$, \code{upper\_bound(x)}를 첫 $>x$ 위치로 해석한다.
\item vector iterator를 \code{it - v.begin()}으로 index로 바꾼다.
\item 값 $x$의 개수를 두 bound의 차이로 계산한다.
\item $[L,R]$ 안의 원소 개수를 두 bound의 차이로 계산한다.
\item \code{end()}를 dereference하지 않고 안전하게 처리한다.
\item sort preprocessing과 Q개의 query를 합친 전체 complexity를 설명한다.
\item static sequence와 dynamic ordered container 사이를 update 패턴으로 구분한다.
\item \code{binary\_search}와 bounds의 반환 정보 차이를 설명한다.
\end{enumerate}

\section{Part C --- 개념과 원리}

\subsection{C1. 정렬은 query를 위한 전처리다}
정렬된 sequence에서는 작은 값 영역과 큰 값 영역이 분리된다. 이 구조를 이용하면 반복 query에서 경계를 logarithmic search로 찾을 수 있다.

$N$개 값을 한 번 정렬하고 $Q$개의 query를 처리하면 대표적으로
\[
O(N\log N+Q\log N)
\]
이 된다.

\subsection{C2. \code{std::sort}}
\begin{lstlisting}
sort(v.begin(), v.end());                 // ascending
sort(v.begin(), v.end(), greater<int>()); // descending
\end{lstlisting}
$N$개 원소의 comparison sort는 $O(N\log N)$으로 분석한다.

\subsection{C3. Custom comparator와 strict ordering}
점수 내림차순, 이름 오름차순:
\begin{lstlisting}
struct Record {
    string name;
    int score;
};

bool cmp(const Record& a, const Record& b) {
    if (a.score != b.score) {
        return a.score > b.score;
    }
    return a.name < b.name;
}
\end{lstlisting}

comparator는 “a가 b보다 앞에 와야 하는가?”를 답한다. 완전히 동률이면 false가 되어야 하므로 다음과 같은 비엄격 비교는 잘못된 comparator가 될 수 있다.
\begin{lstlisting}
return a.score >= b.score; // wrong
\end{lstlisting}

\begin{keybox}[Tie-break]
문제가 점수 내림차순, 동점이면 이름 오름차순이라고 요구한다면 첫 기준이 같을 때 두 번째 기준까지 비교한다.
\end{keybox}

\subsection{C4. \code{sort}의 안정성}
\code{std::sort}는 comparator상 동등한 원소의 원래 상대 순서를 보존한다고 가정하면 안 된다. 원래 순서 보존이 요구되면 \code{stable\_sort} 또는 명시적 tie-break를 검토한다.

\subsection{C5. Bounds의 전제}
bounds는 정렬된 범위에 사용해야 한다.
\begin{lstlisting}
sort(v.begin(), v.end());
auto lo = lower_bound(v.begin(), v.end(), x);
auto hi = upper_bound(v.begin(), v.end(), x);
\end{lstlisting}
custom ordering을 썼다면 검색도 그 ordering과 호환되어야 한다.

\subsection{C6. \code{lower\_bound}}
오름차순 vector에서
\begin{lstlisting}
auto it = lower_bound(v.begin(), v.end(), x);
\end{lstlisting}
은 첫
\[
v[i]\ge x
\]
위치를 반환한다. 없으면 \code{end()}다.

예를 들어
\[
v=[1,2,2,2,5,7]
\]
이면 lower bound of 2는 index 1, lower bound of 3은 index 4, lower bound of 8은 \code{end()}다.

\subsection{C7. \code{upper\_bound}}
\begin{lstlisting}
auto it = upper_bound(v.begin(), v.end(), x);
\end{lstlisting}
은 첫
\[
v[i]>x
\]
위치를 반환한다.

같은 vector에서 upper bound of 2는 index 4, upper bound of 3도 index 4, upper bound of 7은 \code{end()}다.

\begin{conceptbox}[핵심]
lower bound는 첫 $\ge x$, upper bound는 첫 $>x$다.
\end{conceptbox}

\subsection{C8. Duplicates와 반열린 구간}
값 $x$인 원소는 정확히
\[
[\operatorname{lower\_bound}(x),\operatorname{upper\_bound}(x))
\]
에 놓인다.

따라서
\begin{lstlisting}
auto lo = lower_bound(v.begin(), v.end(), x);
auto hi = upper_bound(v.begin(), v.end(), x);
long long count = hi - lo;
\end{lstlisting}
로 중복 개수를 계산할 수 있다.

\subsection{C9. Iterator를 index로 바꾸기}
vector iterator는 random-access iterator이므로
\begin{lstlisting}
int idx = lower_bound(v.begin(), v.end(), x) - v.begin();
\end{lstlisting}
처럼 index를 얻을 수 있다. 반환값이 \code{end()}이면 index는 \code{v.size()}다. 단 \code{end()}는 실제 원소가 아니므로 dereference하면 안 된다.

\subsection{C10. 값 구간의 개수}
$[L,R]$의 원소 개수:
\[
\operatorname{upper\_bound}(R)-\operatorname{lower\_bound}(L)
\]

\begin{center}
\begin{tabular}{ll}
\toprule
원하는 구간 & 원소 개수 \\
\midrule
$[L,R]$ & \code{upper\_bound(R) - lower\_bound(L)} \\
$[L,R)$ & \code{lower\_bound(R) - lower\_bound(L)} \\
$(L,R]$ & \code{upper\_bound(R) - upper\_bound(L)} \\
$(L,R)$ & \code{lower\_bound(R) - upper\_bound(L)} \\
\bottomrule
\end{tabular}
\end{center}

공식을 외우기보다 왼쪽에서는 어떤 값부터 허용하는지, 오른쪽에서는 어떤 값부터 제외하는지를 각각 결정한다.

\subsection{C11. Predecessor와 successor}
\begin{itemize}
\item $x$ 이상 최소값: \code{lower\_bound(x)}
\item $x$ 초과 최소값: \code{upper\_bound(x)}
\item $x$ 미만 최대값: \code{prev(lower\_bound(x))}, 단 iterator가 \code{begin()}이 아니어야 함
\item $x$ 이하 최대값: \code{prev(upper\_bound(x))}, 단 iterator가 \code{begin()}이 아니어야 함
\end{itemize}

\subsection{C12. \code{binary\_search}와 bounds}
\begin{lstlisting}
bool exists = binary_search(v.begin(), v.end(), x);
\end{lstlisting}
\code{binary\_search}는 존재 여부를 반환한다. bounds는 위치를 반환하므로 첫 위치, 중복 개수, 삽입 위치, 구간 개수, predecessor/successor에 사용할 수 있다.

\subsection{C13. sorted vector vs set/multiset}
\begin{center}
\begin{tabularx}{\textwidth}{p{3.6cm}XX}
\toprule
구조 & 강점 & 약점 \\
\midrule
sorted \code{vector} & static 데이터에 단순하고 locality가 좋고 duplicates 보존이 자연스럽다 & 중간 insert/erase는 보통 $O(N)$ \\
\code{set} & dynamic insert/erase/bound가 $O(\log N)$ & duplicates 제거, node overhead \\
\code{multiset} & duplicates 보존 + dynamic ordered update & node overhead \\
\bottomrule
\end{tabularx}
\end{center}

\subsection{C14. 전체 lifecycle complexity}
정렬 $O(N\log N)$, Q개의 bound query $O(Q\log N)$이므로 전체는
\[
O(N\log N+Q\log N)
\]
이다.

입력 vector의 명시적 저장은 $O(N)$이다. \code{std::sort}의 auxiliary space를 표준 인터페이스 수준에서 무조건 $O(1)$이라고 단정하지 않는다. auxiliary space가 평가 대상이면 구현과 분석 범위를 분명히 한다.

\subsection{C15. 사용하면 안 되는 상황}
\begin{itemize}
\item query가 한 번뿐이고 선형 탐색이면 충분한 경우
\item query 사이에 insert/erase가 매우 자주 일어나는 경우
\item 원래 index 순서 자체가 문제의 핵심인 경우
\item 정렬되지 않은 범위에 bounds를 호출하려는 경우
\item answer space에 대한 Binary Search 문제
\end{itemize}

\section{Part D --- Worked Example}

\subsection{D1. 문제 --- Price Range Queries}
$N$개의 체결 가격이 주어진다. duplicates가 허용된다. 이어서 $Q$개의 query $[L,R]$가 주어진다. 각 query마다
\begin{enumerate}
\item $L\le p\le R$인 가격의 개수
\item 그런 가격이 있으면 최소 가격, 없으면 \code{NONE}
\end{enumerate}
를 출력한다고 하자.

예시 데이터:
\[
[8,3,5,5,10,2]
\]

\subsection{D2. Brute Force}
query마다 모든 가격을 훑으면 한 query가 $O(N)$, 전체가 $O(NQ)$이다.

\subsection{D3. Complexity}
$N,Q\le200000$이라면 $NQ$는 최대 약 $4\times10^{10}$ 규모가 되므로 반복 선형 scan은 부적절하다.

\subsection{D4. Bottleneck}
원본 가격은 바뀌지 않는데 query마다 같은 배열을 처음부터 다시 순회하는 것이 병목이다.

\subsection{D5. 핵심 관찰}
한 번 정렬하면
\[
[8,3,5,5,10,2]\longrightarrow[2,3,5,5,8,10]
\]
이 된다. $[L,R]$에 속하는 값은 정렬된 vector에서 하나의 연속 구간을 이룬다.

왼쪽 경계는 첫 $\ge L$이므로 \code{lower\_bound(L)}, 오른쪽 바깥 경계는 첫 $>R$이므로 \code{upper\_bound(R)}다.

\subsection{D6. 알고리즘 설계}
\begin{enumerate}
\item 가격을 vector에 저장한다.
\item 한 번 sort한다.
\item query마다 \code{left = lower\_bound(L)}, \code{right = upper\_bound(R)}를 구한다.
\item 개수는 \code{right-left}.
\item \code{left != right}이면 최소값은 \code{*left}.
\end{enumerate}

\subsection{D7. 정확성}
\code{left} 앞의 모든 값은 $L$보다 작고, \code{right} 앞까지의 값은 $R$ 이하다. 따라서
\[
[\code{left},\code{right})
\]
에는 정확히 $L\le p\le R$인 값만 들어 있다. 그러므로 iterator 차이가 정확한 개수이며, 구간이 비어 있지 않다면 첫 원소가 최소값이다.

\subsection{D8. C++ 구현}
\begin{lstlisting}
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int N, Q;
    cin >> N >> Q;

    vector<long long> price(N);
    for (long long& x : price) {
        cin >> x;
    }

    sort(price.begin(), price.end());

    while (Q--) {
        long long L, R;
        cin >> L >> R;

        auto left = lower_bound(price.begin(), price.end(), L);
        auto right = upper_bound(price.begin(), price.end(), R);

        cout << (right - left) << ' ';

        if (left == right) {
            cout << "NONE\n";
        }
        else {
            cout << *left << '\n';
        }
    }
}
\end{lstlisting}

\subsection{D9. Trace}
정렬 후 vector는
\[
[2,3,5,5,8,10]
\]
이다.

\begin{itemize}
\item $[4,8]$: lower index 2, upper index 5, count 3, minimum 5
\item $[6,7]$: 두 boundary가 모두 index 4, count 0, \code{NONE}
\item $[5,5]$: lower index 2, upper index 4, count 2, minimum 5
\end{itemize}

\subsection{D10. Edge Cases}
\begin{itemize}
\item 모든 값이 같은 경우
\item query 범위가 전체 데이터보다 왼쪽 또는 오른쪽인 경우
\item $L=R$
\item 정확히 한 원소만 포함되는 경우
\item bound가 \code{end()}인 경우
\item $N=1$
\end{itemize}

전체 시간복잡도는
\[
O(N\log N+Q\log N)
\]
이고 명시적 입력 저장 공간은 $O(N)$이다.


\section{보충 Q\&A --- Iterator Type과 가능한 연산}

\subsection{Iterator는 pointer-like abstraction이다}
Iterator는 container 또는 sequence의 한 위치를 나타내며, 그 위치의 원소에 접근하고 다음 위치로 이동하기 위한 객체다. 문법은 pointer와 비슷하지만 반드시 raw pointer인 것은 아니다.

\begin{lstlisting}
vector<int> v = {10, 20, 30};

vector<int>::iterator it = v.begin();
cout << *it;   // 10

++it;
cout << *it;   // 20
\end{lstlisting}

실전에서는 긴 실제 타입 대신 \code{auto}를 자주 사용한다.

\begin{lstlisting}
auto it = v.begin();
\end{lstlisting}

\subsection{\code{iterator}와 \code{const\_iterator}}

\begin{lstlisting}
vector<int> v = {10, 20, 30};

vector<int>::iterator it = v.begin();
*it = 99; // allowed

vector<int>::const_iterator cit = v.cbegin();
// *cit = 99; // error
\end{lstlisting}

\code{const\_iterator}는 iterator가 가리키는 원소를 읽을 수는 있지만 그 iterator를 통해 수정할 수는 없다. const container의 \code{begin()}은 읽기 전용 iterator를 반환하며, \code{cbegin()}과 \code{cend()}를 사용하면 non-const container에서도 읽기 전용 순회를 명시할 수 있다.

\subsection{Iterator category}
C++17에서 핵심 iterator category는 input, output, forward, bidirectional, random-access이다. C++20 iterator concepts에서는 contiguous iterator가 random-access보다 더 강한 category로 추가된다.

\begin{center}
\begin{tabularx}{\textwidth}{p{3.2cm}X}
\toprule
Category & 핵심 능력 \\
\midrule
Input & \code{*it}로 읽고 \code{++it}로 전진하는 single-pass 순회 \\
Output & \code{*it = value} 형태의 쓰기와 \code{++it} 전진 \\
Forward & forward traversal + multi-pass; 같은 sequence를 반복 순회 가능 \\
Bidirectional & forward + \code{--it} 후진 \\
Random-access & bidirectional + \code{it+n}, \code{it-n}, \code{+=}, \code{-=}, \code{it[n]}, iterator 차이와 순서 비교 \\
Contiguous (C++20) & random-access + 원소가 실제 저장소에서도 연속 배치됨 \\
\bottomrule
\end{tabularx}
\end{center}

\subsection{대표 container의 iterator category}

\begin{center}
\begin{tabularx}{\textwidth}{p{4.2cm}X}
\toprule
대상 & iterator 성질 \\
\midrule
\code{vector}, \code{array}, \code{string} & random-access; 저장소는 contiguous \\
\code{deque} & random-access, non-contiguous \\
\code{list} & bidirectional \\
\code{forward\_list} & forward \\
\code{set}, \code{map}, \code{multiset}, \code{multimap} & bidirectional \\
\code{unordered\_set}, \code{unordered\_map} 계열 & forward \\
\code{istream\_iterator} & input \\
\code{ostream\_iterator} & output \\
\bottomrule
\end{tabularx}
\end{center}

\subsection{가능한 대표 연산}
\begin{itemize}
\item 읽기 가능한 iterator: \code{*it}
\item 객체 원소: \code{it->member}는 보통 \code{(*it).member}의 축약
\item 한 칸 전진: \code{++it}, \code{it++}
\item bidirectional 이상: \code{--it}, \code{it--}
\item random-access: \code{it+n}, \code{it-n}, \code{it += n}, \code{it -= n}
\item random-access: \code{it[n]}는 대략 \code{*(it+n)}
\item random-access: 같은 range의 두 iterator에 대해 \code{b-a}
\item random-access: \code{a < b}, \code{a <= b}, \code{a > b}, \code{a >= b}
\end{itemize}

\begin{keybox}[S1-B에서 중요한 차이]
\code{vector<int>::iterator}는 random-access이므로 \code{right-left}가 가능하다. \code{set<int>::iterator}는 bidirectional이므로 \code{right-left}를 사용할 수 없다.
\end{keybox}

\subsection{\code{next}, \code{prev}, \code{advance}, \code{distance}}

\begin{lstlisting}
auto a = next(it, 3);   // it is unchanged
auto b = prev(it, 2);   // bidirectional or stronger

advance(it, 5);         // it itself moves

auto d = distance(first, last);
\end{lstlisting}

Random-access iterator에서 여러 칸 이동과 두 iterator 사이 distance 계산은 보통 $O(1)$이다. Forward/bidirectional iterator에서는 실제로 한 칸씩 이동해야 하므로 $O(n)$이 될 수 있다.

\begin{lstlisting}
set<int> s = {1, 3, 5, 7};

auto it = s.find(7);
auto idx = distance(s.begin(), it); // O(N), not O(1)
\end{lstlisting}

\subsection{Algorithm이 요구하는 iterator}
\begin{itemize}
\item \code{find}: input iterator 수준으로 가능
\item \code{copy}: 읽는 쪽 input iterator + 쓰는 쪽 output iterator
\item \code{reverse}: bidirectional 이동뿐 아니라 원소 swap 가능성도 필요
\item \code{sort}: random-access iterator가 필요하므로 vector/deque/array에는 가능하지만 list/set에는 직접 사용할 수 없음
\item generic \code{lower\_bound}: forward iterator로도 호출할 수 있지만 random-access가 아니면 iterator 이동 총량이 선형일 수 있음
\end{itemize}

\begin{keybox}[\code{set}에서는 member \code{lower\_bound}]
\begin{lstlisting}
set<int> s;

auto it = s.lower_bound(x); // O(log N)
\end{lstlisting}

ordered tree container에서는 member function이 tree 구조를 직접 사용한다. 반대로

\begin{lstlisting}
auto it = lower_bound(s.begin(), s.end(), x);
\end{lstlisting}

처럼 generic algorithm을 사용하면 comparison 수는 logarithmic일 수 있어도 bidirectional iterator를 전진시키는 총 비용은 $O(N)$이 될 수 있다.
\end{keybox}

\subsection{\code{begin}/\code{end}와 반열린 range}
STL의 전형적인 range는
\[
[\code{begin()},\code{end()})
\]
이다. \code{end()}는 마지막 원소가 아니라 마지막 원소 다음 위치다.

\begin{lstlisting}
for (auto it = v.begin(); it != v.end(); ++it) {
    cout << *it << '\n';
}
\end{lstlisting}

따라서 \code{*v.end()}는 잘못이다. Bidirectional iterator이고 range가 비어 있지 않다면 \code{--end()} 또는 \code{prev(end())}로 마지막 원소에 갈 수 있다.

\subsection{Associative container iterator의 수정 가능성}

\begin{lstlisting}
map<int, string> mp;
auto it = mp.begin();

// it->first = 10;   // error: key is const
it->second = "new";  // allowed
\end{lstlisting}

\code{map<K,V>::value\_type}은 \code{pair<const K,V>}다. key를 iterator를 통해 바꾸면 ordering 자체가 깨질 수 있으므로 key는 수정할 수 없다. \code{set}에서도 저장된 key를 iterator로 직접 수정할 수 없다.

\subsection{Reverse iterator}

\begin{lstlisting}
for (auto it = v.rbegin(); it != v.rend(); ++it) {
    cout << *it << ' ';
}
\end{lstlisting}

reverse iterator에서는 \code{++it}가 underlying sequence에서는 뒤쪽 원소에서 앞쪽 원소 방향으로 이동한다.

\subsection{Iterator invalidation}
Iterator는 container 수정 뒤에도 자동으로 안전한 것이 아니다.

\begin{itemize}
\item \code{vector}: reallocation이 일어나면 기존 iterator가 모두 무효화된다. reallocation이 없어도 insert/erase 위치 이후 iterator는 영향을 받을 수 있다.
\item \code{list}, \code{map}, \code{set}: 일반적인 insert는 기존 iterator를 보존하며, erase는 지운 원소의 iterator를 무효화하는 것이 기본 패턴이다.
\item unordered container: rehash가 발생하면 iterator가 무효화될 수 있다.
\end{itemize}

\subsection{실전 점검 순서}
\begin{enumerate}
\item 어느 container에서 나온 iterator인가?
\item iterator category는 무엇인가?
\item 읽기 전용인가, 원소 수정이 가능한가?
\item \code{++}만 필요한가, \code{--}도 필요한가, \code{+n}이나 subtraction까지 필요한가?
\item algorithm이 요구하는 iterator category와 writable/swappable 성질을 만족하는가?
\item container 수정 뒤 iterator가 invalidate되지 않았는가?
\end{enumerate}


\section{Part E --- 중간평가}

\subsection{E-1. Static Score Queries}

\begin{problembox}{Intermediate Assessment --- Static Score Queries}
정수 점수 $A_1,\dots,A_N$이 처음에 한 번 주어지고 이후에는 변경되지 않는다. 이어서 $Q$개의 query가 주어진다.

각 query는 다음 세 종류 중 하나다.
\begin{itemize}
\item \code{1 x}: $A_i<x$를 만족하는 점수의 개수를 출력한다.
\item \code{2 x}: $A_i=x$를 만족하는 점수의 개수를 출력한다.
\item \code{3 L R}: $L<A_i\le R$을 만족하는 점수의 개수를 출력한다.
\end{itemize}

\textbf{구현 및 제출 조건}
\begin{itemize}
\item C++17로 완전한 프로그램을 작성한다.
\item 모든 query를 주어진 최대 제약조건 안에서 처리할 수 있어야 한다.
\item 코드와 함께 전체 시간복잡도와 공간복잡도를 $N,Q$를 사용하여 설명한다.
\item 사용한 정수 타입이 안전한지 설명한다.
\item 최소 두 개의 edge case를 제시한다.
\item \code{T\_solve}를 직접 측정하여 함께 제출한다. 문제를 읽기 시작한 시점부터 accepted-quality final code가 완성될 때까지를 측정한다.
\item compiler/run은 사용할 수 있다. 문제 해설·정답 검색, 다른 사람이나 AI의 도움, 현재 시도에 대한 힌트 또는 접근 검토는 사용할 수 없다. 표준 C++ 문법/API 확인만 허용한다.
\end{itemize}

\textbf{제약 조건}
\begin{TextBlock}
1 <= N, Q <= 200000
-1000000000 <= A_i <= 1000000000
-1000000000 <= x, L, R <= 1000000000
L <= R
\end{TextBlock}

\textbf{Input}

첫째 줄에 $N$과 $Q$가 주어진다.

둘째 줄에 $N$개의 정수 $A_1,\dots,A_N$이 주어진다.

다음 $Q$개의 줄에는 각 query가 한 줄에 하나씩 주어진다.

\textbf{Output}

각 query에 대한 답을 한 줄에 하나씩 출력한다.

\textbf{Sample Input}
\begin{TextBlock}
8 6
5 1 5 2 9 5 7 2
1 5
2 5
3 2 7
1 -10
2 2
3 9 9
\end{TextBlock}

\textbf{Sample Output}
\begin{TextBlock}
3
3
4
0
2
0
\end{TextBlock}
\end{problembox}

\subsection{E-1 제출 및 판정}

\begin{answerbox}[학습자 제출 코드]
\begin{lstlisting}
#include <iostream>
#include <string>
#include <algorithm>
#include <vector>
#include <map>
#include <unordered_map>
#include <set>
#include <unordered_set>

using namespace std;

int main()
{
    int N = 0;
    cin >> N;
    int Q = 0;
    cin >> Q;
    vector<int> v = {};
    for (int i = 0; i < N; i += 1) {
        int Ai = 0;
        cin >> Ai;
        v.push_back(Ai);
    }
    sort(v.begin(), v.end());
    for (int i = 0; i < Q; i += 1) {
        int a = 0;
        int x = 0;
        int L = 0;
        int R = 0;
        cin >> a;
        auto bgn = v.begin();
        if (a == 1) {
            cin >> x;
            auto low_b = lower_bound(v.begin(), v.end(), x);
            auto up_b = upper_bound(v.begin(), v.end(), x);
            cout << low_b - bgn << '\n';
        }
        else if (a == 2) {
            cin >> x;
            auto low_b = lower_bound(v.begin(), v.end(), x);
            auto up_b = upper_bound(v.begin(), v.end(), x);
            cout << up_b - low_b << '\n';
        }
        else if (a == 3) {
            cin >> L >> R;
            auto low_b = upper_bound(v.begin(), v.end(), L);
            auto up_b = upper_bound(v.begin(), v.end(), R);
            cout << up_b - low_b << '\n';
        }
    }
}
\end{lstlisting}
\end{answerbox}

\paragraph{학습자 제출 분석.}
학습자는 전체 시간복잡도를 $O(N\log N+Q\log N)=O((N+Q)\log N)$, 저장 공간을 $O(N)$으로 설명했다. 정수 범위가 \code{int}에 안전하다고 판단했고 두 개의 edge case를 제시했다. 제출한 풀이 시간은 \code{T\_solve = 11:29}다.

\paragraph{판정: PASS.}
세 query 구현은 모두 정확하다. Type 1은 \code{lower\_bound(x)-begin()}으로 $x$ 미만 개수를, Type 2는 \code{upper\_bound(x)-lower\_bound(x)}로 $x$와 같은 값의 개수를, Type 3은 \code{upper\_bound(R)-upper\_bound(L)}로 $L<A_i\le R$의 개수를 계산한다.

제출 코드는 C++17로 컴파일되었고 sample, 제출한 두 edge case, 2,000개 randomized differential test를 모두 통과했다. 전체 시간복잡도 결론은 정확하다. 다만 ``마지막 원소라면 모든 원소를 탐색한다''는 설명은 부정확하다. random-access iterator를 사용하는 \code{lower\_bound}/\code{upper\_bound}는 범위를 절반씩 좁혀 logarithmic comparison search를 수행한다.

전체 저장 공간은 입력 vector 때문에 $O(N)$이다. 정수 값과 query 값은 \code{int}에 안전하며 iterator 차이의 크기는 최대 $N$이다. 실제 iterator 차이의 타입은 \code{vector<int>::difference\_type} 계열이라는 점은 별도로 구분한다.

Type 1의 \code{up\_b}는 계산하지만 사용하지 않는 비차단 불필요 코드다.
